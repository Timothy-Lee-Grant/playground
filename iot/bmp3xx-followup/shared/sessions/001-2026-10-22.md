## 4. Discoveries
- **Verified** (`009`, h0): on a BMP390, raising pressure OSR to ×32 while in normal mode at 5 ms sets conf_err (ERR 0x04) and drops the chip to sleep (PWR_CTRL 0x03) within 5 ms, 10/10. So the chip checks a settings change in normal mode like entering it. **Unverified:** the same for an ODR change (the simulator models it; comment says unverified).
- **Verified** (`004`): the binding reports a `Read()` timeout as `(null, null)`, not an exception; Copilot's "Read() can time out" shows up as a null temperature in the tests.
- **Verified** (`003`): all 89 original tests pass with the stricter F1 simulator, so none of them exercised a repeated normal request.
- **Verified** (code + XML doc): `Read()` in normal mode starts no forced measurement; the plan's Step 3.1 / Step 6 (i) wording ("SetPowerMode(Normal) again → Read()") would not exercise F2. Tests and hw-check go to sleep first.
- **Verified** (`010-prepr-review`): the only open PR matching "Bmp3xx" (#2630, Copilot, GPIO lifetimes) touches no Bmp3xx file.
- **Unverified:** a redundant PWR_CTRL normal write on the real chip doesn't restart/end the running measurement (the F1 simulator assumption); (i) passing 45/45 is consistent with it but doesn't prove it.
