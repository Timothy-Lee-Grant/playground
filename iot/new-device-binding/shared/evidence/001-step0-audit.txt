--- 4b. Extra facts (plan Step 0.4) ---
[✔] Reset values (DS390 Table 25, p.30): OSR 0x02 (osr_p x4, osr_t x1), ODR 0x00, CONFIG 0x00, PWR_CTRL 0x00,
    CMD 0x00, ERR 0x00, STATUS 0x00, EVENT 0x01,
    DATA_0..2 = 00 00 80, DATA_3..5 = 00 00 80  -> raw pressure = raw temperature = 0x800000 (8,388,608) after reset.
    Same in DS388.
    !! U5 caveat: a real raw temperature near room temperature is also ~8.3-8.4 million (T1 typ ~27000*2^8 ≈ 6.9M,
       T2 ≈ 1.8e-5 °C/LSB -> 25 °C ≈ 6.9M+1.4M), so a genuine reading can, rarely, equal exactly 0x800000.
       Checking BOTH raw values == 0x800000 makes a false "no data" vanishingly rare and harmless (next read OK).
       (estimate, unverified until E1 gives real raw values)
[✔] Burst read required for consistency (data shadowing; "strongly recommended to use a burst read",
    "must use burst reads if he does not synchronize ...") DS390 §3.10-3.10.1, p.27
[✔] Register auto-increment on READ: "Multiple byte read (using a single register address which is
    auto-incremented)" DS390 §5 p.40; §5.2.2 p.41
[!] I2C multi-byte WRITE is "using pairs of register addresses and register data" (DS390 §5 p.40; §5.2.1 p.41),
    NOT auto-increment. -> Plan Step 8's fake ("following input bytes are written to consecutive registers")
    would model the chip wrongly. Binding writes one register per transaction anyway.
[✔] Power-on: sleep mode after POR (§3.2, §3.3.1 p.11); tstartup 2 ms (Table 2 p.8)
[✔] Forced mode returns to sleep automatically: "When the measurement is finished, the sensor returns to sleep
    mode ... For a next measurement, forced mode needs to be selected again." DS390 §3.3.2 p.11
[?] Mode transitions: §3.3.4 p.13 "mode change commands that are not legal are ignored"; Figure 4 is vector art
    (arrows not extractable without a renderer). Which transitions are legal (esp. Normal -> Forced) is
    UNVERIFIED. Mode switch during a measurement is delayed until the measurement ends.
[✔] Normal-mode rule: max normal-mode rate from the measurement time: odr_sel >= ceil(log2(200 Hz / f_max)),
    f_max = 1e6 / Tconv[µs] (DS390 §3.9.2 p.27); conf_err reports a bad configuration in normal mode (Table 28).
    O5 note: x1/x1 at 200 Hz: typ 4.82 ms < 5 ms OK, but MAX 5.70 ms > 5 ms. Whether the chip raises conf_err
    for this is UNVERIFIED (defaults are written in sleep mode, where conf_err isn't evaluated).
[✔] IIR filter is reset when CONFIG is written, when press_en/temp_en go 1->0, and on sleep->normal (§3.4.3 p.15)
[✔] Calibration scaling (DS390 Appendix §8.4 p.55), identical in DS388 §9.x:
    T1 = NVM/2^-8 (= x2^8) · T2 = /2^30 · T3 = /2^48 · P1 = (NVM-2^14)/2^20 · P2 = (NVM-2^14)/2^29 ·
    P3 = /2^32 · P4 = /2^37 · P5 = NVM/2^-3 (= x2^3) · P6 = /2^6 · P7 = /2^8 · P8 = /2^15 · P9 = /2^48 ·
    P10 = /2^48 · P11 = /2^65     -> all 14 match plan Step 7's table
[✔] Compensation (Appendix §8.5-8.6 p.55-56): t = (rawT - T1)*T2 + (rawT - T1)^2 * T3;
    p = (P5 + P6 t + P7 t^2 + P8 t^3) + rawP*(P1 + P2 t + P3 t^2 + P4 t^3) + rawP^2*(P9 + P10 t) + rawP^3 * P11
    -> matches plan Step 7's description. (The appendix is itself Bosch C code with float temporaries;
       clean room: implement from the formulas, own names, no "partial_data" etc.)
[✔] BMP388 vs BMP390, section-by-section text diff (PWR_CTRL..CONFIG, STATUS, calibration table, compensation,
    I2C write, forced mode, shadowing): only numbering/whitespace differs. Real differences:
      chip ID 0x50 vs 0x60 · T_conv constants (above) · REV_ID 0x01 exists only on BMP390 ·
      EVENT bit1 itf_act_pt only on BMP390 · conf_err "only working in normal mode" wording only in DS390 ·
      sleep/forced current slightly different (3.4 vs 3.2 µA @1 Hz). Ranges identical.
