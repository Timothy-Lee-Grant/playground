## 4. Discoveries
All of these are from the Stage 5 entries. Each one is labeled as that entry labeled it.
- **Code reading (*unverified* by reading; proven by tests in run 2):** brief §3 holds. `ButtonBase.cs:73`
  `IsPressed` starts `false`; `GpioButton.cs:87-91` opens the pin and registers the callback but never reads it;
  `ButtonBase.cs:126` swallows the first release when debounce is on.
- **PR #2608 collisions (then head `a1563be0`):** none on our lines. Possible trivial adjacent-hunk conflict only.
  (Superseded: #2608 has since moved to `6a2f8973`; see session 003 / `evidence/007`.)
- **Test harness:** `MockableGpioDriver` is **linked** from `System.Device.Gpio.Tests` (3 in-repo precedents),
  not copied. `VirtualGpioController` (Board) was rejected: it adds a big dependency and routes events through its
  own pin objects. Moq 4.20.72 reaches every test project (`eng/Versions.external.props:13`).
- **Mock gotchas:** `MockBehavior.Loose` returns `false` for `IsPinModeSupportedEx`, so the ctor throws unless the
  test sets it up. `ReadEx` defaults to Low, which silently means "pressed" for pull-up. `CallBase = true` is
  required. `FireEventHandler` runs the callback **synchronously on the test thread**.
- **U2 correction:** callbacks run on driver-owned background threads (SysFs, libgpiod v1/v2), and `IsPressed` is
  unlocked. Register-then-read still leaves a small **lost-update window**: if an edge's callback runs between
  `Read()` returning and the assignment, the ctor overwrites the newer value. Closing that window fully needs a
  lock in `ButtonBase`, which is out of scope. No test can reproduce it.
- **Brief §4 correction:** raising `ButtonDown` in the ctor reaches no subscriber, so "would recreate #1715" is the
  wrong reason. The real reasons: no press happened; and keeping the fix side-effect-free survives a later lazy-
  subscription refactor.
- **Two plan tests are guards, not red tests** (pull-up/High and pull-down/Low pass on `main`). They were kept to
  catch a wrong fix.
