## 4. Discoveries
- **Verified (019, 022, 023): leaving normal mode while a measurement runs, the BMP390 ignores a new mode until the
  measurement ends, silently (no ERR bit), while PWR_CTRL already reads sleep.** Settings writes (OSR) stick. This
  broke `SetPowerMode(Forced)` from Normal and Normal→Sleep→Normal, and caused hw-check (b) to "not throw". Bosch's
  driver waits a fixed 5 ms, which 019 shows isn't enough for long measurements. Fixed in `69009f1a`.
- **Verified (019):** conf_err is set within 0.34 ms and the chip drops to sleep at once; the binding's measurement-time
  formula matches the chip's conf_err rule on every row tested (84). My first explanation of (b) ("conf_err set late",
  and the CHANGE REQUEST built on it) was wrong and is withdrawn in plan.md.
- **Verified (018):** a direct normal→forced write is ignored (closes the 2026-10-05 finding 3: the sleep detour is needed).
- **Verified (018, 023):** normal mode at the default 5 ms ×1/×1 works → default ODR stays (no O5 change).
- **Verified (018):** real BMP390 calibration bytes `4B6B034CF9151E6817060121480D5A03FA531008F5`; ~21.2 °C / 1015.0 hPa.
- **Verified (023):** the wait margin (measurement time + 10% + 1 ms) held at x32/x32 15/15. Size of the real spread: unverified.
- **Unverified:** whether leaving *forced* mode mid-measurement behaves the same (assumed; the fix covers it); which
  settings a running normal-mode measurement uses after OSR changes in normal mode (the fix takes the max).
- **Verified (commit `c8e4589f` in the merge):** Timothy's GpioButton fix (#2611) is merged upstream.
- `dotnet test` on SDK 10 rejects `--no-incremental`: build first, then `test --no-build` (`run-tests.sh`).
